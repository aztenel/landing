# Модуль «Сайт» (ТЗ 05) — раунд 4

Один Laravel, два адреса: ERP на `erp.<домен>`, сайт-каталог на `<домен>` (`config/prime.php`: `erp_domain`, `shop_domain`).
Сайт читает только таблицы `storefront_*` и пишет только `site_leads` / `site_stats`.

## Как работает

| Часть | Где |
|---|---|
| Формула «почему не на сайте» (§4.1) — одна на всё | `app/Domain/Storefront/Services/Visibility.php` |
| Сборка публичной карточки целиком из склада (§8.2) | `Services/ListingBuilder.php` (`units`, `all`, `stores`, `accessories`) |
| ERP → сайт: outbox в транзакции → слушатель | `Listeners/SyncStorefront.php` (темы `document.posted/reversed`, `unit.changed`, `site.changed`), `Support/SiteChange.php` |
| Фото: приватный оригинал, EXIF удаляется, квадрат, WebP xl/lg/md/sm + og JPEG, случайные имена | `Services/Photos.php` |
| Настройки сайта (шаблоны WhatsApp, рассрочка, грейды) | `Services/SiteSettings.php` (`organizations.settings.storefront`) |
| Анонимные заявки СЗ-… (§11) | `Services/Leads.php`, таблица `site_leads` |
| Поиск: сленг, русская раскладка, PM/PA-код | `Services/Search.php` |
| Ночная сверка 03:40 (§8.6) | `prime:site-reconcile`, таблица `storefront_runs` |
| Публичные страницы | `routes/modules/storefront.php`, `app/Http/Controllers/Storefront`, `app/Http/Storefront`, `resources/views/storefront` |
| Раздел «Сайт» в ERP (§14) | `app/Filament/Site/Pages/Site.php` (`/site`) |
| Вкладка «Сайт» в паспорте (Э10.4) | `app/Livewire/Stock/UnitPassport.php`, `resources/views/stock/partials/passport-site.blade.php` |
| Поиск ERP по «СЗ-1001» и PM-коду | `app/Support/Ui/ErpSearch.php` |

Где сайт обновляется сам: продажа, сторно, возврат, резерв, перемещение, приход (документы), смена цены (`PriceService`),
госбаза (`ImeiCheckService`), фото, переключатели, справочник, магазины, настройки.

## Страницы сайта (§9.1)

`/`, `/catalog/{smartfony|planshety|chasy|naushniki|aksessuary}/{бренд}`, `/bu`, `/model/{slug}`, `/phone/PM-…` (+ slug),
`/PM-…` (короткий), `/item/PA-…`, `/search`, `/store`, `/trade-in`, `/rassrochka`, `/garantiya`, `/privacy`, `/go/wa`,
`/sitemap.xml`, `/robots.txt`. Казахский — те же адреса с `/kk`.

Фильтры — обычные GET-ссылки (работают без JavaScript), свёртка одинаковых новых «в наличии 7», страница «Продан»
с похожими, Product/Offer/BreadcrumbList/Store/Organization, hreflang, canonical, Open Graph с фото `og`.
Готовый HTML кэшируется по «версии сайта» фирмы (любая пересборка карточки меняет версию).

Пока сайт выключен — покупатели видят «Скоро», `robots.txt` закрывает всё. Сотрудники открывают сайт кнопкой
«Открыть сайт» в ERP (подписанная ссылка, режим предпросмотра на 8 часов). Включить сайт нельзя, пока
«Политика конфиденциальности» — черновик (§9.12).

## Права

`site.photo` — фото; `site.visibility` — показать/скрыть, «Новые фото», «Товары»; `site.order` — закрепить, «Хит»;
`site.description` — описание; `site.rules` — категории, бренды, модели, магазины; `site.content` — страницы, баннеры;
`site.leads` — заявки; `site.settings` — настройки. Фото продавца к телефону, который уже на сайте, публикуется
сразу и попадает в «Новые фото» на проверку (§3.5).

## Проверено

12 автотестов (`tests/Feature/Storefront`): фото → на сайте; в файлах нет EXIF и кода товара; в HTML нет IMEI,
14+ цифр подряд, себестоимости и поставщика; продажа → «Продан»; свёртка новых и фото модели; скрытие модели и
возврат; старая цена и «−6 %»; заявка с kk-страницы → WhatsApp магазина с кодом СЗ, продажа закрывает заявку;
поиск «айфон», «шзрщту», код; выключенный сайт; модерация фото продавца; ночная сверка исправляет испорченную
цену; вкладка паспорта; раздел «Сайт» (заявки, категории с числом, магазины, страницы, настройки рассрочки,
баннеры, пересборка). Chrome 109 и эмуляция iPhone 12: без ошибок в консоли и без горизонтальной прокрутки.
Скриншоты — `docs/screens/site/`.

## Что не сделано (честно)

- **Акции** (§6.3) — нет. Старая цена ставится галочкой при смене цены.
- **Порядок перетаскиванием** (§5.2, «Сайт → Порядок») — нет; есть «Поднять наверх» / «Обычный порядок» в паспорте.
- Распознавание IMEI на фото (§3.5) и «светлый фон» (§3.4) — нет (нужна модель на сервере). Подсказка «тёмное фото» есть.
- HEIC: сервер не конвертирует. Safari на iPhone при выборе из галереи обычно отдаёт JPEG; иначе — подсказка
  «Настройки → Камера → Наиболее совместимый».
- Обработка фото идёт сразу в запросе, не в отдельной очереди `storefront-media` (для 1 магазина достаточно).
- Отдельный пользователь базы «только storefront_*» (§1) — при развёртывании (раунд 6).
- Предоценка trade-in на сайте — выключена (ТЗ: этап 8). «Позвоните мне» — не сделана (по ТЗ выключена).
- Характеристики модели (экран, процессор…) — таблицы нет, блок на карточке скрыт (как разрешает ТЗ).
- Казахские тексты интерфейса сайта — черновой перевод, нужен просмотр Кайрата.
- Счётчики: просмотры и запросы без результата — есть; «Сайт за 7 дней» в Статистике владельца — в раунде 5.
- На сервере `upload_max_filesize` / `post_max_size` должны пропускать 25 МБ (раунд 6, развёртывание).
- Для цели «продажа на сайте ≤ 15 с» на сервере `prime:outbox` должен работать постоянно (supervisor), а не раз в минуту.
