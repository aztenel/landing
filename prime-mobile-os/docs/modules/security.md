# Безопасность входа, приложение на iPhone, сервер (ТЗ 03 §7–9, архитектура §6) — раунд 7

## Вход по коду (2FA)
- Код из приложения (Google Authenticator, «Пароли» iOS), стандарт TOTP RFC 6238 — `app/Domain/Shell/Services/TwoFactor.php`.
- **Обязателен** для владельца, админа и бухгалтера; остальным — по настройке фирмы `security.two_factor_all`.
- Первая настройка — QR и ключ вручную, затем **10 резервных кодов** (показываются один раз, хранятся только хэши).
- 5 неверных кодов → пауза 15 минут. «Запомнить это устройство на 30 дней» — только личное устройство, не компьютер магазина.
- Владелец в «Сотрудники и роли» может «Сбросить код входа» сотруднику, потерявшему телефон.
- Секрет хранится зашифрованным. Выключается только переменной `PRIME_TWO_FACTOR=false` — она стоит лишь в автотестах и на компьютере разработчика.

## PIN разблокировки
`Мой профиль → PIN этого устройства`: 4–6 цифр, не простые (1234, 0000…), свой у каждого человека на каждом устройстве, только хэш.
Экран блокировки принимает PIN или пароль; 5 ошибок — полный выход.

## Мой профиль (`/profile`)
Язык интерфейса **Русский / Қазақша**, PIN, вход по коду, «Выйти везде, кроме этого устройства».

## Казахский язык ERP
`lang/kk.json` — меню, кнопки, статистика, касса, склад, вход (188 строк). **Черновой перевод** — проверить носителем языка;
непереведённые надписи остаются по-русски. Сайт и печатные формы — на двух языках с раундов 4–5.

## Приложение на iPhone (PWA)
Ставится «На экран Домой» (manifest, иконки уже были). Добавлен service worker `public/sw.js`: кэширует только статические
файлы и страницу «Нет связи» (`public/offline.html`). Страницы с данными не кэшируются (ТЗ 03 §8.3).

## Сервер, выпуск, копии
`deploy/README.md` — установка по шагам: nginx с двумя пулами PHP (касса и сайт отдельно), supervisor (очередь и
`prime:outbox --loop` — продажа уходит с сайта за секунды), cron, отдельная роль базы для сайта
(`deploy/postgres/site_role.sql` + `DB_SITE_USERNAME`), ночные зашифрованные копии restic в другое место в РК
(`deploy/backup/backup.sh`), еженедельная проверка восстановления в staging, выпуск без простоя с автоматическим откатом
(`deploy/scripts/release.sh`), `/health` для мониторинга, уведомление владельцу, если копия не прошла.
Автотесты на GitHub — `.github/workflows/prime-mobile-os.yml`.

## Проверено
`tests/Feature/Security`: тестовый вектор RFC 6238; владельца отправляет на настройку кода; 10 резервных кодов; новая сессия
снова спрашивает код; 5 ошибок — пауза; резервный код срабатывает один раз; продавца код не спрашивает; сброс владельцем;
PIN — простые и без пароля нельзя, хэш; казахский интерфейс по выбору в профиле; `/health`.

## Не проверено
- **Ничего из `deploy/` не запускалось на настоящем сервере** (сервера пока нет): права роли сайта, восстановление копии, выпуск.
- iOS: код из «Паролей», «На экран Домой» и service worker на реальном iPhone.
- **Не сделано:** вход бейджем + PIN на компьютере магазина; повторный PIN перед опасными действиями (§10) — есть только
  пароль для крупных заявок; passkey / Face ID; pgBackRest «на любую минуту» (сейчас ночные копии).
