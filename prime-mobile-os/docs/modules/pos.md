# Модуль «Касса» (pos) — Э3

Экран: `/sale` — `app/Filament/Pos/Pages/Sale.php`, разметка `resources/views/pos/pages/sale.blade.php`. Логика: `App\Domain\Pos\Services\CartService`.

## Как устроено

- **Корзина хранится на сервере** (`pos_carts`): продавец × магазин × вкладка (до 5, F7). В корзине только id, количество, скидки и оплаты; **цены всегда из прайса** в момент показа и проведения. Перезагрузка, второй телефон или ожидание заявки ничего не теряют.
- Телефон в чеке = бронь ядра (`ReservationService`), «Уже в корзине у Айдара до 15:20».
- **Проведение**: черновик продажи с ключом `pos:<cart>:<key>:<version>` — двойной клик и повтор после потери ответа дают один чек. Любое изменение корзины повышает версию и сбрасывает заявку: разрешение владельца покрывает ровно тот чек, о котором просили.
- **Заявка**: `checkout()` → `approval` → «Запросить у владельца» (`ApprovalService::requestForDocument`) → экран ждёт ответа (`wire:poll` 3 с) → после «Разрешить» чек проводится сам.
- **Смена**: без открытой смены — окно пересчёта касс (`ShiftCash::open`), закрытие — `ShiftCash::close`; в плашке магазина «Смена с 09:00».
- **Магазин работы**: `App\Support\Ui\WorkingStore` — продавец работает в своём магазине; у кого несколько — выбирает (сессия). Магазин из браузера не принимается без проверки.

## Точки для других модулей

| Что | Контракт |
|---|---|
| Trade-in (F8) | **подключён**: `App\Domain\TradeIn\TradeInPosProvider` открывает акт `/tradein/new?tab=N` в режиме «в зачёт». Акт-черновик встаёт в чек (`CartService::attachTradeIn`), при «Провести» акт и чек проводятся одной операцией, акт первым (`Poster::postMany`). |
| Печать чека | маршрут `erp.pos.receipt` (`/sale/receipt/{document}`), вид `pos.receipt` — временный чек 80 мм. Модуль печати (Ф1) заменяет **вид**, имя маршрута оставляет. |
| Продажа по заказу | `CartService::loadOrder($cart, $user, $order)` — телефон, клиент и предоплата заказа. |
| Возврат (F10) | пока сообщение; модуль чеков/возвратов подключит переход. |
