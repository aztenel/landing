# Модуль «Перенос из sfon» (ТЗ 07 §1) — раунд 6

Экран `/migration` — только владелец. Вкладки: Чек-лист Ш0–Ш11 · Файлы и API · Доработать · День X: скан · Проведение ·
Сверка · Архив sfon · Отключение. Импорт никогда не пишет в живой учёт: файл/API → сырые строки (`import_rows`) →
проверка → «Входящие остатки» (ВХО) → проведение.

| Часть | Файл |
|---|---|
| Клиент Open API sfon (только чтение, `X-API-Key`, 2 запроса/с, 429 → пауза 60 с) | `app/Domain/Migration/Services/SfonClient.php` |
| «Забрать из sfon»: магазины (WhatsApp, 2ГИС, скрытие на сайте), справочник, телефоны в наличии (новые группами, б/у поштучно с фото и описанием) | `SfonPull.php`, `Catalogs.php` |
| Excel из sfon: клиенты, долги клиентов и поставщикам, бонусы, аксессуары, себестоимость по IMEI, история продаж в архив; колонки — по названиям | `ExcelImport.php` |
| День X: скан IMEI забирает строку sfon (новые — группа варианта, б/у — выбор карточки), «лишние» с моделью и ценой, отчёт качества, ВХО по магазину | `DayX.php` |
| Ночная сверка 03:00 (параллельная работа): новые — шт. по варианту × магазин, б/у — по sfon_id, цены; вероятная причина; «дней без расхождений» | `SfonReconcile.php`, `prime:sfon-reconcile` |
| Архив истории sfon: поиск по IMEI, номеру чека, телефону; IMEI из архива виден в поиске ERP | таблица `sfon_archive`, `app/Support/Ui/ErpSearch.php` |

**Ключ API sfon** вписывается только в `.env` на сервере: `SFON_API_KEY=…`. В репозитории и в чате его нет. Без ключа
экран честно пишет «Ключ API sfon не задан»; сверка ночью не запускается.

Правила, которые проверяет система:
- ВХО проводит только владелец и только после шага Ш6 (списки долгов и бонусов проверены и подписаны);
- второй раз ВХО того же магазина не проводится;
- повторная загрузка файла или API не создаёт дублей, строки уже в ВХО не меняются;
- телефон без себестоимости проводится с флагом «себестоимость неизвестна» — не продаётся, пока её не внесут;
- б/у сохраняет `sfon_id` для ночной сверки;
- отключение — только при всех 7 условиях (14 дней, 5 сверок подряд без расхождений, приёмка, бэкап, ссылки, подпись).

## Проверено
`tests/Feature/Migration/MigrationTest.php` — с подставным API sfon (настоящего ключа нет): забор магазинов, справочника
и склада без изменения живого учёта и без дублей; Excel по названиям колонок; день X целиком (скан, повтор, ошибка IMEI,
«все отсканированы», б/у, лишний, отчёт качества, запрет без Ш6 и не владельцу, проведение с аксессуарами, деньгами,
долгами в ₸ и $, бонусами); ночная сверка: 0 расхождений, затем продажа у нас → расхождение с номером нашего чека.

## Не проверено
- **Настоящий API sfon** — нет ключа. Имена полей справочника (`nameRu`, `nameKz`) взяты из спецификации; ответы
  справочников в спецификации не описаны — сверить на первом заборе (шаг Ш1).
- **Колонки Excel sfon** — подбираются по названиям; точные названия узнаем на разведке Ш2.
- Скачивание фото б/у с `shop.sfon.kz` в день X — не сделано (ссылки сохраняются, фото можно снять заново).

# Акции сайта (ТЗ 05 §6.3) — раунд 6
«Сайт → Акции» (`price.bulk`): название ru/kk, период, фильтр (категория, модели, новые/б/у, коды), −% / −₸ / фикс.
цена, округление вниз, старая цена. «Предпросмотр» — было/станет и «ниже себестоимости» (по праву). Старт и конец — по
часам (`prime:promotions-tick`): цены меняются документами смены цены, касса продаёт по той же цене; в конце цена
возвращается, кроме изменённых вручную — они в уведомлении владельцу «решите сами». Метка акции на карточке — пока
не выводится (видна скидка «−5%»).

# Сводки владельцу (ТЗ 06 §4) — раунд 6
`prime:summaries` каждую минуту: в 09:00 (настройка) «Итог вчера», в понедельник «Итог недели», 1-го «Итог месяца»,
в 22:30 «Итог дня». Цифры — те же функции, что в отчётах. Без имён и телефонов клиентов, ИИН, IMEI; продавец — только
имя. Уходят как уведомление владельцу (в колокольчик; в Telegram/пуш — по настройкам уведомлений).
