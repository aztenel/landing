## 0. Коротко

- **Перенос в два слоя** (архитектура 5): живые остатки, долги, кассы и бонусы заводятся одним документом «Входящие остатки» (`ВХО`) на день X; вся история sfon — в архив только для чтения. История в живые журналы не проигрывается.
- **IMEI берём только сканом в день X.** В Open API sfon IMEI нет (проверено по спецификации). Каждый телефон в магазине проходит через сканер, иначе он не попадает в продажу.
- **Себестоимость, долги и кассы подписывает Кайрат** по печатным спискам. Подпись — условие проведения `ВХО`.
- **Параллельная работа минимум 14 дней**, ночная сверка с sfon через API, отключение sfon только после 5 дней подряд без расхождений и письменного согласия Кайрата.
- **Приёмка — по пунктам «Проверено, если…»** для каждого процесса и экрана плюс 58 тестовых сценариев с цифрами. Каждый сценарий проверяется на трёх устройствах: ноутбук Windows 7 / Chrome 109 (1366×768), iPhone 12, iPhone 17 Pro Max.
- **Полноценная версия 1.0** — это ERP, касса, склад, деньги, долги, trade-in, отчёты, сайт с синхронизацией, перенос и отключение sfon. Оценка: **9–10 недель** от старта при вовремя полученных выгрузках. Второй филиал, Telegram-бот и интеграции (Webkassa, Kaspi XML, ЭСФ) — после сдачи, отдельными этапами.
- **Сдача** = рабочая система + документы + доступы на имя Кайрата + проверенный бэкап + акт сдачи-приёмки.

## 1. Перенос из sfon

### 1.1 Принципы

1. **День X** — дата, с которой живые цифры считаются в Prime Mobile OS. Всё, что было до него, — архив.
2. **Входящие остатки — это обычный документ** (`ВХО`, раздел 02, п. 2.3). Он пишет записи во все четыре журнала (товар, деньги, долги, бонусы). Ошибку в нём исправляют сторно, как в любом документе. Отдельной «правки после импорта» нет.
3. **Каждый перенесённый объект хранит `sfon_id`** (номер в sfon) и ссылку на строку импорта. По ним идёт ночная сверка и поиск «откуда это взялось».
4. **Импорт повторяемый.** Один и тот же файл или ответ API можно загрузить сколько угодно раз: повторная загрузка обновляет промежуточные строки по `sfon_id` и не создаёт дублей. Живые журналы импорт не трогает, пока не проведён `ВХО`.
5. **Все репетиции — на staging** (`staging.<домен>`, отдельная база, архитектура 6). На рабочую базу `ВХО` проводится один раз, в день X.
6. **Ключ API sfon** хранится только в `.env` сервера (архитектура 6). Кайрат передаёт его интегратору лично, не через чат.
7. **Что не удалось перенести — записываем честно.** В отчёте переноса есть раздел «Не перенесено» с причиной; для таких данных хранятся скриншоты и PDF в архиве.

### 1.3 Ограничения sfon и как обходим

Из [`00-sfon-paritet.md`](00-sfon-paritet.md) (по текстам экранов; на живом аккаунте не проверено).

| Ограничение | Как обходим |
|---|---|
| Статистика и Excel — максимум за 1 месяц | Выгружаем помесячно, файлы называем `sfon_<экран>_<ГГГГ-ММ>.xlsx`. Скрипт импорта склеивает месяцы и проверяет, что нет пропущенных |
| Выгрузка склада — максимум 1 000 строк | Выгружаем с фильтрами (по магазину, по типу, по семейству), чтобы в каждом файле было < 1 000. В отчёте разведки — сумма строк по файлам против числа товаров в API |
| В API нет IMEI, себестоимости, клиентов, долгов, продаж, касс | Скан в день X, списки Кайрату на подпись, письменный запрос |
| Ключ API с датой окончания, лимит запросов | Узнать дату окончания на шаге Ш0. Запросы — не чаще 2 в секунду (Допущение), страницы по 100 записей, при ответе «слишком много запросов» — пауза 60 с и повтор |
| Данные API с задержкой несколько секунд | Ночная сверка идёт в 03:00, когда магазин закрыт; задержка не мешает |
| «Мягкое удаление» товаров и накладных в sfon | Удалённые записи в Excel могут попадать или нет (не проверено). При разведке сверяем число строк с экраном sfon |
| Массовая смена курса в прошлых заказах | Суммы в $ из архива sfon считаем справочными; в ₸ берём ту сумму, что в Excel на дату выгрузки, с пометкой «курс мог быть изменён в sfon» |

### 1.4 Промежуточные таблицы (модуль «Перенос»)

Импорт никогда не пишет прямо в живые таблицы. Схема: **файл/API → сырые строки → проверка → черновик `ВХО` → проведение**.

| Таблица | Что хранит |
|---|---|
| `import_runs` | один запуск: фирма, источник (`api` / `excel` / `manual`), тип данных, файл, кто, когда, итог (строк всего / ок / с ошибкой / пропущено) |
| `import_rows` | одна строка источника как есть (JSON), `sfon_id`, статус (`новая` / `сопоставлена` / `ошибка` / `пропущена` / `в ВХО`), текст ошибки, ссылка на наш объект |
| `import_mappings` | соответствие значений: «iPhone 15 Pro Max» в sfon → наш вариант; «Kaspi Gold» в sfon → наш счёт. Заполняется один раз, используется всеми запусками |
| `migration_checklist` | пункты шагов Ш0–Ш11: статус, кто отметил, когда, вложения (подписанные сканы списков) |
| `sfon_reconciliations` | результаты ночных сверок: дата, расхождений всего, по типам, ссылка на отчёт |
| `sfon_archive_*` | архив истории (п. 1.10), только чтение |

Промежуточные таблицы удаляются через 12 месяцев после отключения sfon (Допущение). Архив остаётся навсегда.

### 1.5 Соответствие полей (основное)

Точные имена колонок Excel узнаем на шаге Ш2 (разведка). Ниже — что точно должно совпасть.

**Справочник (API `dictionaries/*`):**

| sfon | Наше поле | Правило |
|---|---|---|
| id | `sfon_id` | ключ сопоставления |
| name ru | `name_ru` | как есть |
| name kz | `name_kk` | если пусто — в список «нет перевода»; без `name_kk` ценник не печатается ([`00-kazakhstan.md`](00-kazakhstan.md), п. 9) |
| name en | `name_en` | как есть |
| код памяти «256» | память `256 ГБ` | числа → наш справочник; «1TB» → `1 ТБ` |
| цвет | цвет | разные написания («Black», «Чёрный», «черный») сводим через `import_mappings` |

**Б/у телефон (API `products/old/{productId}`):**

| sfon | Наше поле | Правило |
|---|---|---|
| productId | `stock_units.sfon_id` | ключ ночной сверки |
| модель/память/цвет/ОЗУ | `variant_id` | через справочник; не нашли — строка «ошибка: нет варианта» |
| год | `year` | 2015–текущий; иначе пусто + предупреждение |
| АКБ | `battery_pct` | 0–100; иначе пусто |
| описание | `defects_text` | как есть; грейд A/B/C ставит Кайрат при подготовке, по умолчанию пусто (Допущение) |
| цена | розничная цена ₸ | > 0 |
| фото | файлы экземпляра | скачиваем с `shop.sfon.kz/storage`, обрабатываем как свои (05, п. 3.3) |
| магазин | `store_id` | через `stores.sfon_id` |

**Новые телефоны (API `products/search`, группой):** вариант + магазин + количество + средняя цена. Мы создаём **N черновиков экземпляров без IMEI** со статусом импорта «ждёт скана». В день X каждый скан IMEI «забирает» один черновик этого варианта (п. 1.7).

**Клиенты (Excel):** телефон приводим к `+7XXXXXXXXXX`; два клиента с одним телефоном — объединяем, имя берём из более поздней записи, в строке пометка. Без телефона — клиент не переносится в живые, остаётся в архиве (Допущение).

**Долги (Excel или вручную):** клиент/поставщик, сумма, валюта, дата возврата, комментарий. Долг в $ — сумма в $ и курс дня X (02, п. 3.5: `avg_rate` = курс дня X).

### 1.6 Шаги переноса

**Правила ревизии-скана в режиме «Перенос»:**

| Что отсканировали | Что делает система |
|---|---|
| IMEI нового телефона, есть черновик этого варианта в магазине | забирает один черновик, ставит IMEI, счётчик варианта «7 из 8» |
| IMEI б/у | Допущение: у б/у в sfon IMEI нет в API, поэтому после скана продавец выбирает карточку б/у из короткого списка «б/у этой модели без IMEI» (фото + цена + АКБ). Это единственное место, где экземпляр выбирают из списка (исключение из правила 01, п. 0.3), потому что IMEI ещё некуда сравнить |
| IMEI, а модель неизвестна | окно «Какой это телефон?»: выбор варианта, новый/б/у, цена; строка уходит в «лишние» |
| Тот же IMEI второй раз | «Уже отсканирован (строка 41)», двойной звук |
| IMEI не проходит Луна | «IMEI с ошибкой» — переснять или ввести вручную с *#06# |
| Штрихкод коробки вместо IMEI | подсказка (01, п. 0.3) |

**Разбор итогов:**
- **Лишние** (физически есть, в sfon нет): создаётся экземпляр в `ВХО` с пометкой «найден при переносе»; себестоимость вводит Кайрат на месте; если не знает — Допущение: себестоимость = 0 и флаг «уточнить себестоимость», продажа такого телефона блокируется до ввода (01, П3.7).
- **Не найдено** (в sfon есть, физически нет): не попадает в `ВХО`. Список «Найти» печатается; Кайрат отмечает причину: продан и не проведён в sfon / у мастера / дома / потерян. Если телефон найдётся — обычный приход с пометкой «найден после переноса».
- **Не в том магазине** — пока один магазин, не бывает.

### 1.8 Параллельная работа

Архитектура 5, шаг 7: минимум 14 дней.

| Период | Главная система | Что делают продавцы | Что делает Кайрат |
|---|---|---|---|
| Дни 1–4 | **sfon** | каждую операцию сначала в sfon, затем сразу же в Prime Mobile OS (это и есть обучение) | смотрит «Статистику» в обеих, принимает заявки в новой |
| Дни 5–14 | **Prime Mobile OS** | сначала в новой (печать чека и талона — из новой), затем дублируют в sfon | работает только в новой; sfon — запасной |
| После 14-го дня | Prime Mobile OS | дублирование до отключения sfon (п. 1.11) | решает об отключении |

**Правила дублирования:**
1. Дублировать в течение **10 минут** после операции, не в конце дня (Допущение).
2. Дублируются все операции: продажа, возврат, приход, trade-in, расход, оплата долга, курс $.
3. В новой системе в комментарии документа ничего ставить не нужно — сверка идёт по IMEI и суммам.
4. Сайт на время параллели: остаётся старым (shop.sfon.kz) в дни 1–4; новый сайт включается на домене с 5-го дня, если этап 4 принят (Допущение). Ссылки в Instagram и 2ГИС меняются после включения.
5. Пропустили операцию — утром её покажет сверка; доводится документом с хоз. датой той операции (задним числом до 3 дней — админ или владелец, 03, право 80). Старше 3 дней — сегодняшней датой с комментарием «доввод за <дата>».
6. **Ответственный от магазина** каждый вечер ставит отметку «День сверен» на экране «Перенос» после сверки итогов смены в обеих системах (продажи шт. и ₸, касса ₸).

|---|---|---|---|
| Продано телефонов, шт. | 6 | 6 | 0 |
| Выручка, ₸ | 2 314 000 | 2 314 000 | 0 |

### 1.9 Ночная сверка с sfon

Автоматически в 03:00 (архитектура 5). Отчёт утром в Telegram Кайрату и интегратору и на экране «Перенос → Сверка».

**Что сравнивается:**

| Объект | Как | Расхождение, если |
|---|---|---|
| Новые телефоны в наличии | количество по варианту × магазину (API sfon `products/search` против наших `в наличии` + `в резерве` + `на подготовке`) | количество отличается хоть на 1 |
| Б/у в наличии | поштучно по `sfon_id`; новые б/у после дня X — по варианту + цене + АКБ (Допущение) | есть только в одной системе |
| Розничные цены | по варианту (новые: средняя цена sfon против нашей цены варианта); б/у — поштучно | разница > 0 ₸ |
| Аксессуары | по штрихкоду, если API их отдаёт (не проверено); иначе — вручную раз в неделю по Excel | количество отличается |
| Деньги, долги | API не даёт — только вечерняя ручная сверка (п. 1.8) | — |

**Пример сообщения:**

> Сверка с sfon за 14.11: 2 расхождения.
> 1) iPhone 15 Pro 256 Natural, Керуен: sfon 4, у нас 3. В sfon нет продажи ПРД-2026-004901 (Дана, 13.11, 18:42) — не задублировали в sfon.
> 2) Samsung A55 Синий: цена sfon 229 000, у нас 219 000. Смена цены 13.11 (Кайрат) не задублирована в sfon.
> 5 дней без расхождений: 0 из 5.

**Подсказка причины.** Для каждого расхождения система ищет документы за последние 3 дня, которые его объясняют (продажа, возврат, приход, смена цены), и пишет «вероятная причина». Если не нашла — «причина не найдена, проверьте вручную».

**Счётчик «дней без расхождений»** сбрасывается на 0 при любом расхождении, у которого причина — ошибка нашей системы или неучтённая операция. Расхождения «не задублировали в sfon» тоже сбрасывают счётчик (Допущение: строго, как в архитектуре).

### 1.10 Архив истории sfon

| Вариант | Когда | Что делаем |
|---|---|---|
| **А. sfon прислал полную выгрузку** | после ответа на письмо | Загрузка в `sfon_archive_sales`, `_sale_lines`, `_receipts`, `_returns`, `_customers`, `_debts`, `_expenses`, `_transfers` (как есть, плюс наши ссылки на клиента и экземпляр по IMEI) |
| **Б. Только Excel помесячно** | если sfon не ответил за 14 дней | Загружаем Excel-файлы помесячно в те же таблицы, недостающие поля — пусто. В отчёте переноса — «не перенесено: <что>» |
| **В. Нет ничего** | если и Excel неполный | Скриншоты и PDF ключевых отчётов по месяцам (выручка, прибыль) в папку архива; в системе — только итоги по месяцам вручную |

**Что видно из архива:**
- поиск по IMEI в шапке: «Продан в sfon 12.03.2025, клиент Ерлан +7 701 … , гарантия до 12.03.2026» (если IMEI есть в выгрузке);

- в «Отчётах» — переключатель «включить архив sfon» для выручки и прибыли по месяцам (прибыль — только если в выгрузке есть себестоимость);
- в паспорте телефона, проданного до дня X и вернувшегося (trade-in), — строка «История в sfon».

**Проверка архива:** выручка по каждому месяцу из архива = выручке из отчёта sfon за тот же месяц (Кайрат снимает скриншоты отчётов до отключения). Допуск — 0 ₸; при разнице — список чеков месяца для поиска.

### 1.11 Отключение sfon

**Все условия сразу** (архитектура 5, шаг 9), отмечаются на экране «Перенос → Отключение»:

1. ≥ 14 дней параллельной работы.
2. 5 ночных сверок подряд без расхождений.
3. Принят этап «Приёмка» (раздел 3–6 этого документа): все блокирующие замечания закрыты.
4. Финальная выгрузка sfon сохранена в наш бэкап: ответы API (JSON), все Excel, скриншоты отчётов по месяцам. Проверено, что файлы открываются.
5. Ключ API sfon не нужен для ночной сверки (сверка выключается этим же шагом).
6. Ссылки в Instagram, 2ГИС, WhatsApp-профиле ведут на новый сайт.
7. Кайрат подписал «Согласие на отключение sfon» (лист в комплекте сдачи, раздел 9).

**После отключения:** Кайрат не продлевает подписку sfon (Допущение: не удаляем аккаунт sfon до конца оплаченного месяца, чтобы при необходимости посмотреть). Экран «Перенос» переходит в режим «только чтение».

## 2. Как проводится приёмка

1. **Где:** на рабочем сервере (production) в учебной фирме «Prime Mobile — Тест» (Допущение: отдельная фирма на том же сервере, её данные не попадают в отчёты Prime Mobile; удаляется после сдачи) и на staging для разрушающих проверок (отключение Redis, восстановление бэкапа).
2. **Устройства** (каждый пункт, если не сказано иное):

| Код | Устройство | Где использовать |
|---|---|---|
| **НБ** | ноутбук магазина, Windows 7, Chrome 109, 1366×768, USB-сканер, режим «старый ноутбук» включён | касса, склад, отчёты, печать |
| **iП** | iPhone 12 (самый слабый поддерживаемый), Safari, PWA | мобильная касса, сканер камерой |
| **iВ** | iPhone 17 Pro Max, PWA | статистика, заявки, приход, фото на сайт |

3. **Кто принимает:** Кайрат (или ответственный от магазина по его поручению) вместе с интегратором. Интегратор ведёт таблицу приёмки (Допущение: файл в репозитории без персональных данных; облачные таблицы не используем, чтобы данные клиентов не уходили за пределы РК).
4. **Статусы пункта:** «Принято» / «Замечание: блокирующее» (мешает работать, считает деньги неправильно, раскрывает данные) / «Замечание: неблокирующее» (неудобно, опечатка) / «Перенесено в следующий этап» (только с согласия Кайрата).
5. **Правило сдачи:** все блокирующие закрыты и перепроверены; неблокирующих не больше 15 (Допущение), у каждого срок исправления в гарантийный период.
6. **Автотесты.** Каждый сценарий раздела 6, где это возможно, оформлен разработчиком как автотест (Laravel feature-тест или браузерный тест). Сценарии с пометкой «руками» проверяются только вручную. Перед каждым деплоем на production все автотесты зелёные (архитектура 6).

## 3. Критерии приёмки процессов (П1–П22)

| Процесс | Проверено, если… |

| **П1. ## 4. Критерии приёмки экранов (Э1–Э30 и сайт)

Общие для **каждого** экрана (проверяются на НБ, iП, iВ, где экран есть):
- Открывается ≤ 2 с на НБ (Chrome 109), ≤ 1,5 с на iВ (оценка; замер — по 5 открытий, берём среднее).
- В Chrome 109 нет поломанной вёрстки: нет пропавших рамок и фонов (сравнение со снимками `chrome109-*.png` из `docs/design/screens/`).
- В режиме «старый ноутбук» текст не мельче 13 px, нет анимаций и теней.
- Тёмная тема без нечитаемого текста.
- Есть «пустое состояние» с одной понятной кнопкой (04, п. 0.4).
- Все поля, которые роль не должна видеть (себестоимость, прибыль, поставщик, полный ИИН), отсутствуют в ответе сервера, а не только скрыты (проверка: «сохранить страницу» и поиск по тексту).
- Тексты на русском без английских слов интерфейса; переключатель kk работает там, где он есть.

## 7. План работ до сдачи полноценной версии

### 7.1 Что такое «полноценная версия 1.0»

| **9** | 6. Отключение sfon + приёмка | Полная приёмка по разделам 3–6. Исправление замечаний. Нагрузочная проверка (раздел 5). Восстановление бэкапа при Кайрате. Документация | Все блокирующие замечания закрыты | Разделы 3–6 целиком; сценарии 47–49 |
| **10** | Сдача | Отключение sfon (п. 1.11), передача доступов, комплект сдачи, акт сдачи-приёмки. Резерв на задержки (выгрузки sfon, ответы Кайрата) | Версия 1.0 сдана | Раздел 9 |

**Что сдвигает сроки** (архитектура 8): задержка выгрузок sfon и ответов Кайрата — это +1 день к плану за каждый день задержки на неделях 1–5; новые хотелки во время работ идут в список «после 1.0», а не в текущую неделю. Допущение: Кайрат даёт ответственного от магазина на 30–60 минут в день с недели 3.

**Каждую пятницу — показ Кайрату** (20–30 минут, на его iPhone и на ноутбуке магазина): что сделано, что проверить, вопросы недели. По итогам — список замечаний в таблице приёмки.

### 7.3 Гарантийный период после сдачи

Допущение: **30 дней после подписания акта** интегратор бесплатно исправляет ошибки (то, что работает не так, как написано в ТЗ). Новые функции — отдельной оценкой. Срочность:

| Тип | Пример | Реакция (Допущение) |
|---|---|---|
| Авария | касса не проводит продажи, система недоступна | начать ≤ 1 часа в рабочее время магазина |
| Блокирующая ошибка | неверно считается сдача, не печатается талон | ≤ 1 рабочего дня |
| Неблокирующая | опечатка, неудобная кнопка | в ближайший плановый деплой (раз в неделю) |

## 8. Обучение сотрудников: цель — без обучения

**Цель:** новый продавец, знакомый с sfon или вообще без опыта, проводит первую продажу **без инструктажа за ≤ 3 минуты**, а через день работает не медленнее, чем в sfon.

### 8.1 Что заложено в саму систему

| Приём | Где описан | Как проверяем |
|---|---|---|
| Названия разделов и горячие клавиши как в sfon | 04, п. 0.6; 01, п. 0.8 | продавец из sfon находит «Продажу» и F9 без подсказки |
| Продавец сразу попадает в «Продажу», поле скана в фокусе | архитектура 1а | первое действие — скан |
| Ошибки говорят, что делать, без кодов | 01, п. 0.7 | ни одного сообщения с кодом ошибки в приёмке |
| Кнопка неактивна → рядом написано, чего не хватает | 04, п. 0.4 | сценарии 11, 12, 25 |
| Пустые состояния с одной кнопкой | 04, п. 0.4 | раздел 4, общие критерии |
| Подсказка при первом входе: 3 всплывающие подсказки на кассе (скан → оплата → печать), можно закрыть навсегда | Допущение | — |
| Учебная фирма «Prime Mobile — Тест» на staging с ненастоящими телефонами, данные сбрасываются каждую ночь | Допущение | продавец может «нажать всё» без вреда |

### 8.2 Что всё-таки делаем (минимум)

| Кто | Формат | Длительность (оценка) | Когда |
|---|---|---|---|
| Продавцы | **Дублирование в дни 1–4 параллели** — это и есть обучение (архитектура 5). Перед днём X — 15 минут в учебной фирме: продажа, сплит, долг, возврат | 15 мин | неделя 5 |
| Админ / старший продавец | Приход, ревизия, возврат, сторно, закрытие смены, перемещение | 45 мин | неделя 5 |
| Кайрат | iPhone: установить PWA, заявки, статистика, приход камерой, фото на сайт, цены, скрыть/показать, сотрудники и устройства | 45 мин | неделя 5 и неделя 7 (сайт) |
| Бухгалтер | Отчёты, Excel, закрытие месяца | 30 мин | неделя 9 |

### 8.3 Материалы

- **Памятка у кассы**, 1 лист A5, ламинированная: горячие клавиши, «что делать, если нет интернета» (iPhone как касса через мобильный интернет → если сервер недоступен — бумажный журнал), телефон интегратора.
- **Бланк бумажного журнала продаж** (10 листов распечатаны заранее): время, модель, IMEI (последние 6 цифр), цена, способ оплаты, клиент (имя, телефон), продавец, подпись. Используется только при недоступности сервера (сценарий 47).
- **Короткие видео 30–60 с** на экране телефона (Допущение): продажа, сплит, trade-in, возврат, фото на сайт, заявки. Хранятся в разделе «Помощь» системы, не на YouTube.
- **Инструкция владельца** (раздел 9) — для Кайрата, на 10–15 страниц, с картинками экранов.
