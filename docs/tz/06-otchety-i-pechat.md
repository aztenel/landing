## 0. Коротко

1. **Одна формула — везде.** Выручка, прибыль, средний чек и остальное считаются одной функцией для экрана «Статистика», iPhone владельца, отчётов, Excel и уведомлений в Telegram. Если цифры на телефоне и в Excel разошлись — это ошибка, а не «разная методика».
2. **Источник цифр — только проведённые документы и журналы** (раздел 02). Черновики, заявки и резервы в отчёты не попадают.
3. **Нет ограничения периода.** У sfon статистика и Excel — максимум за 1 месяц, выгрузка склада — 1 000 строк ([`00-sfon-paritet.md`](00-sfon-paritet.md), п. 6). У нас любой период и любое число строк.
4. **Себестоимость и прибыль не уходят в браузер** тех, кому они закрыты (раздел 03, п. 4): ни на экране, ни в Excel, ни в PDF, ни в сортировке.
5. **Владелец утром получает итог вчерашнего дня**, вечером — итог сегодняшнего, а важные события (заявки, продажа в минус, сторно) — сразу пушем на iPhone.
6. **Печать — 12 форм** (Ф1–Ф12): чек, гарантийный талон, накладные, акт приёма б/у с ИИН, ценники, термоэтикетки и другие. Все на казахском и русском, казахский — первым на ценнике.
7. **Принтеры Xprinter.** Базовый способ — печать из браузера (шаблон точного размера). Дополнительно — QZ Tray для тихой печати на нужный принтер без окна выбора. С iPhone — печать «на принтер магазина» через очередь.

## 1. Общие правила всех отчётов

### 1.1 Что попадает в отчёт

| Правило | Значение |
|---|---|
| Документы | только `posted` (проведён). Черновики, заявки «ждёт решения», резервы в корзине — нет |
| Сторно | **сторно-документ попадает в отчёт своей датой с обратным знаком.** Если продажа и её сторно в одном периоде — они взаимно гасятся, продажа «исчезает». Если продажа в закрытом месяце, а сторно в открытом (раздел 02, п. 9) — закрытый месяц не меняется, в открытом будет минус |
| Возврат покупателя | отдельный документ, считается **датой возврата**, а не датой исходной продажи. В отчётах — отдельная строка «Возвраты» (раздел 02, п. 2.1, правило 6) |
| Дата | хоз. дата `occurred_at` в часовом поясе фирмы (по умолчанию `Asia/Almaty`). «День» = 00:00–23:59 местного времени |
| Архив sfon | **в живые цифры не смешивается.** В отчётах «Продажи и прибыль» и «Продажи по моделям» есть переключатель «Показать архив sfon» — тогда до дня X строки берутся из архива с серой пометкой «sfon», без себестоимости, если её нет |
| Входящие остатки (день X) | документ ВХО — не продажа и не приход от поставщика. В отчёт «Приходы» не попадает, в «Остатки в деньгах» — попадает |
| Тестовые и учебные данные | только на staging. На рабочей системе «учебных» продаж нет |

### 1.2 Общие фильтры

Каждый отчёт имеет панель фильтров. Не все фильтры есть у всех отчётов — это указано в каталоге (раздел 3).

| Фильтр | Значения | По умолчанию |
|---|---|---|
| Период | Сегодня, Вчера, Эта неделя, Прошлая неделя, Этот месяц, Прошлый месяц, Этот год, Прошлый год, «Свой период» | Этот месяц (у «Статистики» — Сегодня) |
| Сравнить с | Прошлый такой же период, Тот же период год назад, Не сравнивать | Прошлый такой же период |
| Магазин | Все / конкретный. Показывается, только если магазинов больше одного | Все (у админа — его магазин, без выбора) |
| Направление | Электроника / Аксессуары / Всё (переключатель как в sfon) | Всё |
| Продавец | список сотрудников, включая уволенных с пометкой «(уволен)» | Все |
| Тип товара | Смартфон, Планшет, Часы, Наушники, … (справочник) | Все |
| Семейство / модель / вариант | дерево справочника, поиск по названию | Все |
| Состояние | Новый / Б/у | Все |
| Способ оплаты | список счетов и способов (раздел 01, п. 8.2) | Все |
| Источник клиента | список из настроек (Instagram, 2ГИС, сайт, рекомендация, проходил мимо, Kaspi, …) | Все |
| Клиент | поиск по имени или телефону | — |

Правила фильтров:
1. Выбранные фильтры видны строкой над отчётом: «Ноябрь 2026 · Керуен · Электроника · Б/у». Кнопка «Сбросить».
2. Фильтры сохраняются в адресе страницы — ссылку можно отправить бухгалтеру, и у него откроется тот же отчёт (с учётом его прав).
3. Допущение: последний выбранный период запоминается на устройстве для каждого отчёта.
4. Сравнение показывается бейджем «+12 %» зелёным или «−8 %» красным. Для расходов и возвратов цвета наоборот: рост — красный.
5. Если в периоде сравнения ноль, бейдж «новое», а не «+∞ %».

### 1.3 Кто что видит

Сводно по разделу 03 (права `report.*`).

| Роль | Какие отчёты | Себестоимость и прибыль | Excel |
|---|---|---|---|
| Владелец | все, вся фирма | да | да, любой отчёт |
| Бухгалтер | все, кроме «Журнал действий» | да | да |
| Админ | все по своему магазину | себестоимость и поставщик — да (по умолчанию, раздел 03 п. 4.1); прибыль, наценка, маржа — только если в роли включено «Видит прибыль» (по умолчанию выключено) | да, без колонок прибыли (и без себестоимости, если её выключили в роли) |
| Старший продавец | продажи магазина без прибыли, «Залежался» и «Заканчивается» в штуках и рознице | нет | нет |
| Продавец | только «Мои продажи» (Э2.4): чеки, сумма, способы оплаты за 7 дней | нет | нет |

Правила:
1. Закрытые колонки **не приходят с сервера** — это проверяется тестом (раздел 11, Т12).
2. Отчёты, где себестоимость — главная цифра («Остатки в деньгах по себестоимости», «Залежался» в деньгах), у роли без права на себестоимость показывают только штуки и розницу. Отчёты, где главная цифра — прибыль (О-отчёты по прибыли и марже), у админа по умолчанию скрыты целиком.
3. Открытие отчёта с себестоимостью пишется в журнал действий (раздел 03): кто, какой отчёт, период, фильтры. Каждое поле не пишется.

### 1.4 Как отчёт выглядит

Один каркас для всех отчётов (компьютер):

1. **Заголовок** и строка фильтров.
2. **Плитки итогов** (2–5 штук): главные цифры с бейджем сравнения.
3. **График** (если есть у отчёта): столбики по дням / неделям / месяцам (правило из Э2.1: период > 62 дней — по неделям, > 1 года — по месяцам).
4. **Таблица.** Сортировка по любой видимой колонке, строка «Итого» внизу, закреплённая шапка. Пагинация по 50 строк, кнопка «Показать все» до 5 000 строк; больше — только Excel.
5. **Переход вглубь.** Нажатие на строку открывает следующий уровень: модель → варианты → экземпляры → паспорт телефона (Э10); день → чеки дня (Э4) → чек.
6. Кнопки справа сверху: «Excel», «PDF» (печать отчёта на A4), «Поделиться ссылкой».
7. Пустое состояние: «За период данных нет» и подсказка, какой фильтр сбросить.

iPhone: плитки итогов сверху, ниже список карточек вместо таблицы (одна строка таблицы = одна карточка с 2–3 цифрами), фильтры — в шторке снизу. «Excel» → меню «Поделиться» (сохранить в Файлы, отправить в WhatsApp или Telegram).

### 1.5 Скорость

| Требование | Значение |
|---|---|
| Статистика за сегодня | открывается ≤ 1 с |
| Любой отчёт за месяц | ≤ 2 с |
| Любой отчёт за год | ≤ 5 с; если дольше — показывается «Считаем…» и отчёт строится в очереди, приходит уведомление |
| Excel до 50 000 строк | скачивается сразу (≤ 15 с) |
| Excel больше 50 000 строк | собирается в очереди, приходит уведомление «Файл готов», ссылка живёт 24 часа |

Как достигается (для разработчика, без кода):
1. Для закрытых дней ночью строится **сводная таблица** `report_daily` (день × магазин × продавец × вариант или аксессуар × состояние × источник): штуки, выручка, себестоимость, скидки, возвраты. Отдельно `report_daily_payments` (день × магазин × способ оплаты × счёт) и `report_daily_stock` (остаток на конец дня по варианту и магазину: штуки, себестоимость, розница).
2. **Сегодняшний день** считается на лету из документов (их мало).
3. Если проведён документ прошлой датой или сторно старого документа в открытом периоде — в очередь ставится задача «пересчитать сводку за день N». До пересчёта (обычно секунды) отчёт за этот день считается на лету.
4. Каждую ночь сводка сверяется с журналами (раздел 02, п. 13). Не сошлось — тревога интегратору, сводка за день пересобирается.
5. Допущение: сводные таблицы — это копия для скорости, а не источник правды. Если их удалить, они пересобираются из журналов.

## 2. Словарь показателей и формулы

Формулы прибыли — **из раздела 02, п. 5.1**, здесь они повторены для полноты и дополнены отчётными показателями. При расхождении главный — раздел 02.

### 2.1 Продажи и прибыль

| Показатель | Формула | Пример (день 06.11) |
|---|---|---|
| **Продажи (до возвратов)** | Σ сумм строк проведённых продаж **после скидки**, включая услуги (доставка, наклейка стекла) | 3 600 000 ₸ |
| **Возвраты** | Σ сумм возвращённых строк по документам возврата за период | 80 000 ₸ |
| **Выручка** | Продажи − Возвраты | 3 520 000 ₸ |
| **Себестоимость продаж** | Σ `sale_lines.cost_kzt` − Σ себестоимости возвращённых строк | 3 022 000 ₸ |
| **Валовая прибыль** | Выручка − Себестоимость продаж | 498 000 ₸ |
| **Маржа, %** | Валовая прибыль / Выручка × 100 | 498 000 / 3 520 000 = **14,15 %** |
| **Наценка, %** | Валовая прибыль / Себестоимость продаж × 100 | 498 000 / 3 022 000 = **16,48 %** |
| **Комиссии банков** | Σ записей статьи «Комиссия банка» за период | 72 000 ₸ |
| **Оплачено бонусами** | Σ списаний бонусов в оплату − Σ возвращённых при возврате | 5 000 ₸ |
| **Прибыль от продаж** | Валовая − Комиссии − Оплачено бонусами | 421 000 ₸ |
| **Расходы** | Σ проведённых расходов по статьям с признаком «идёт в прибыль» | 35 000 ₸ |
| **Прочее** | списания и недостачи (−), излишки (+), курсовые разницы (±), недостачи/излишки кассы (±) | −2 000 ₸ |
| **Чистая прибыль** | Прибыль от продаж − Расходы ± Прочее | 384 000 ₸ |
| **Чеков** | число проведённых продаж, **кроме полностью возвращённых** и сторнированных | 28 |
| **Средний чек** | Выручка от продаж / Чеков | 3 520 000 / 28 = **125 714 ₸** |
| **Штук продано** | Σ количества в строках продаж − Σ количества возвращённых (телефоны и аксессуары отдельно) | 25 телефонов, 41 аксессуар |
| **Скидки** | Σ (цена по прайсу на момент продажи × кол-во − сумма строки после скидки) | 46 000 ₸ |
| **Скидка, %** | Скидки / (Продажи + Скидки) × 100 | 46 000 / 3 646 000 = **1,26 %** |

Правила (дополняют раздел 02, п. 5.1):
1. **Маржа и наценка — разные цифры, обе подписаны на экране.** Плитка «Прибыль» в Статистике показывает маржу (как в макете `erp-1-statistika.png`: «маржа 14,5 %»). Наценка — в отчётах по моделям и по б/у. Подсказка «?» у каждой объясняет формулу одной строкой.
2. **Trade-in зачёт не уменьшает выручку** (раздел 02, правило 1). Пример: iPhone 16 Pro за 549 000 ₸, из них 150 000 ₸ — зачёт trade-in. Выручка 549 000 ₸, а 150 000 ₸ — это закуп б/у телефона, он виден в отчёте О16.
3. **Рассрочка банка — не долг клиента.** Выручка полная, комиссия — в «Комиссии банков».
4. **Продажа в долг** — выручка в день продажи.
5. **Средний чек** считается только по продажам (без услуг отдельно не делится). Чек с одной услугой «доставка» без товара — Допущение: не бывает (доставка добавляется только к чеку с товаром).
6. Если у строки неизвестна себестоимость (флажок «себестоимость неизвестна», раздел 02, п. 4.1), то в себестоимость идёт 0 ₸, но **над отчётом появляется жёлтая плашка**: «В периоде 3 продажи с неизвестной себестоимостью на 412 000 ₸ — прибыль завышена. Открыть список» → О25.
7. **Цена по прайсу на момент продажи** запоминается в строке продажи (`sale_lines.list_price_kzt`) при проведении. Без неё скидку не посчитать после смены цены. Допущение: поле добавляется в `sale_lines`, если его ещё нет в модели раздела 02.

### 2.2 Склад

| Показатель | Формула | Пример |
|---|---|---|
| **Остаток в штуках** | телефоны: число экземпляров фирмы в статусах `in_stock`, `reserved`, `ordered`, `preparing`, `in_transit`, `defective`; аксессуары: Σ `accessory_balances.qty` | 182 телефона, 1 240 аксессуаров |
| **Остаток по себестоимости** | телефоны: Σ `cost_kzt` этих экземпляров; аксессуары: Σ (кол-во × текущая средняя) | 61 400 000 ₸ |
| **Остаток по рознице** | телефоны: Σ розничных цен; аксессуары: Σ (кол-во × розничная цена) | 72 900 000 ₸ |
| **Ожидаемая прибыль остатка** | Остаток по рознице − Остаток по себестоимости | 11 500 000 ₸ |
| **Остаток в $ (справочно)** | Остаток по себестоимости / действующий курс | 61 400 000 / 515 = $119 223 |
| **Возраст экземпляра, дней** | сегодня − дата **последнего поступления** в фирму (приход, trade-in, возврат покупателя, излишек, входящие остатки) | iPhone 13, принят 10.09 → на 09.11 = 60 дней |
| **Дней до продажи** (у проданного) | дата продажи − дата последнего поступления | 18 дней |
| **Средний остаток по себестоимости за период** | среднее остатков на конец каждого дня периода (из `report_daily_stock`) | 45 000 000 ₸ |
| **Оборачиваемость, раз** | Себестоимость продаж за период / Средний остаток по себестоимости | 60 000 000 / 45 000 000 = **1,33 раза за 30 дней** |
| **Оборот в днях** | Средний остаток / (Себестоимость продаж / число дней периода) | 45 000 000 / (60 000 000 / 30) = **22,5 дня** |
| **Хватит на, дней** (по варианту) | Остаток в штуках / (продано штук за 30 дней / 30) | 3 / (9 / 30) = **10 дней** |

Правила:
1. **Телефон «на подготовке» и «в пути» — тоже остаток** (это деньги фирмы), но в отчётах по складу они видны отдельной колонкой, чтобы не путать с «можно продать сейчас».
2. **Возраст** у возвращённого телефона начинается заново с даты возврата, но в паспорте видна полная история. Допущение: так «залежался» отражает время на полке после последнего поступления.
3. Время «на подготовке» входит в возраст б/у (деньги уже вложены). Отдельной колонкой «из них на подготовке N дней».
4. Если у экземпляра нет розничной цены — в остаток по рознице 0 ₸ и строка в списке «Нет цены» (О7).

### 2.3 Деньги и долги

| Показатель | Формула |
|---|---|
| **Остаток счёта на дату** | Σ записей `money_entries` по счёту с датой ≤ конца дня |
| **Приход по счёту за период** | Σ записей со знаком «+» |
| **Расход по счёту за период** | Σ записей со знаком «−» (по модулю) |
| **Проверка** | Остаток на начало + Приход − Расход = Остаток на конец (если не сходится — ошибка в данных, тревога) |
| **Деньги в кассах (плитка)** | Σ остатков всех счетов в ₸ + Σ счетов в $ × действующий курс |
| **Долг клиента** | Σ `debt_entries` по клиенту (положительный — клиент должен нам) |
| **Просрочка, дней** | сегодня − дата возврата долга (у каждой продажи в долг своя дата) |
| **Долг поставщику** | Σ `debt_entries` по поставщику; в $ — в $ и в ₸ по `avg_rate` (раздел 02, п. 3.5) |

| Колонка | Формула |

#### О14. Движение товара (паспорт склада)

**Доступ:** В, Б, А.
**Фильтры:** период, магазин, тип операции (приход, продажа, возврат, перемещение, списание, ревизия, ВХО, сторно), товар / IMEI.
Это выгрузка журнала `inventory_movements` в понятном виде: дата, документ, операция, товар, IMEI, откуда → куда, кол-во, себестоимость (А*), кто. Для аксессуара — «остаток до» и «остаток после».
Назначение: разобраться, «куда делся чехол», и дать бухгалтеру полный оборот за период.

### Вкладка «Деньги»

#### О15. Движение денег по счетам

**Доступ:** В, Б; А — только счета своего магазина.
**Фильтры:** период, счёт (несколько), статья, магазин.

**Свод по счетам:**

| Счёт | Валюта | Остаток на начало | Приход | Расход | Остаток на конец | Остаток в ₸ (для $ — по текущему курсу) |
|---|---|---|---|---|---|---|
| Касса ₸ — Керуен | ₸ | 1 180 000 | 2 410 000 | 2 345 000 | 1 245 000 | 1 245 000 |
| Касса $ — Керуен | $ | 2 400 | 0 | 0 | 2 400 | 1 236 000 |
| Kaspi QR | ₸ | 3 400 000 | 1 620 000 | 72 000 | 4 948 000 | 4 948 000 |

Проверка в каждой строке: начало + приход − расход = конец. Не сходится — красная строка и тревога интегратору (такого быть не должно).

**Детально по счёту:** каждая запись — дата/время, документ (ссылка), статья, контрагент, приход, расход, остаток после записи, кто. Это «выписка» по счёту.
**По статьям:** приход и расход, сгруппированные по статьям (раздел 02, п. 11.4 `money_articles`).

Правила:
1. Переводы между своими счетами (инкассация, перевод, конвертация) показываются, но в плитке «Чистый поток» не учитываются.
2. **Чистый денежный поток** = приходы по статьям «Выручка», «Оплата долга клиентом», «Предоплата» − расходы по всем статьям, кроме переводов. Это не прибыль: закуп товара уменьшает деньги, но не прибыль. Под плиткой подсказка одной строкой.
3. Для счетов в $ — суммы в $ и в ₸ по курсу каждой записи.

#### О16. Расходы по статьям

**Доступ:** В, Б, А (свой магазин).
**Фильтры:** период, сравнение, магазин, статья, кто провёл, счёт.

| Колонка | Смысл |
|---|---|
| Статья | аренда, зарплата, обед, такси, реклама Instagram, ремонт б/у (если не в себестоимость), гарантийный ремонт, связь, хозрасходы, налоги, регистрация IMEI, … |
| Сумма за период | — |
| Сравнение с прошлым периодом | ₸ и % (рост — красный) |
| % от выручки | сумма статьи / выручка × 100 |
| Число расходов | — |

Переход вглубь: список расходов статьи — дата, № РСХ, описание, сумма, откуда платили (сплит: «20 000 нал + 25 000 Kaspi Gold»), фото чека (иконка), кто провёл, кто разрешил.
Круговая диаграмма не используется — горизонтальные столбики по убыванию (их легче читать на iPhone).
Пример: ноябрь 1–8 — аренда 450 000, зарплата 320 000, реклама Instagram 95 000, обеды 48 000, такси 22 000, прочее 25 000 = 960 000 ₸ (3,95 % от выручки).

«Комиссия банка» и «Курсовая разница» в этом отчёте показываются отдельным блоком «Автоматические расходы», потому что их никто не вводит руками.

#### О17. Смены и кассовые расхождения

**Доступ:** В, Б, А.
**Фильтры:** период, магазин, продавец.

#### О18. Курс доллара и курсовые разницы

**Доступ:** В, Б.
**Фильтры:** период.

1. **История курса:** дата и время, курс, кто поставил, на сколько % изменился. График линией.
2. **Операции в $:** приходы, оплаты поставщикам, конвертации — сумма в $, курс операции, сумма в ₸.
3. **Курсовые разницы:** записи статьи «Курсовая разница» по документам (раздел 02, п. 3.4–3.5). Пример: оплата долга $4 000 при курсе 520 против среднего 515 → −20 000 ₸.

1. **Без персональных данных.** В пушах и Telegram нет имён и телефонов клиентов, ИИН, IMEI. Имена продавцов — только имя. Telegram — сервис вне РК, поэтому туда идут только цифры фирмы ([`00-kazakhstan.md`](00-kazakhstan.md), п. 2).
2. Цифры — из тех же функций, что и отчёты (правило 0.1).
3. Нажатие на пуш открывает нужный экран: «Итог дня» → Статистика за этот день.
4. Если за день не было продаж — «Продаж не было. Магазин работал?» (Допущение: полезная проверка).

## 5. Выгрузка в Excel

### 5.1 Общие правила

1. Кнопка «Excel» есть **у каждого отчёта и у каждого списка** (Склад, Чеки, Клиенты, Долги, Расходы, Журнал движения). Права — раздел 03, строки 21, 92, 93.
2. **Выгружается ровно то, что на экране** с текущими фильтрами и сортировкой, но **все строки**, а не текущая страница. Без ограничения периода и числа строк.
3. Формат — **.xlsx** (Laravel Excel / PhpSpreadsheet, архитектура 1). Для бухгалтера дополнительно «CSV для 1С»: UTF-8 с BOM, разделитель «;», дробная часть через запятую (Допущение: формат подтвердить у бухгалтера).
4. Закрытые колонки (себестоимость, прибыль, поставщик, полный ИИН, полный телефон клиента) **вырезаются на сервере** до формирования файла по правам пользователя.
5. Каждая выгрузка пишется в журнал действий: кто, какой отчёт, фильтры, число строк, с какого устройства.
6. На ноутбуке магазина скачивание файлов выключено для всех, кроме владельца (раздел 03, настройка устройства «Разрешить скачивание файлов»).
7. До 50 000 строк — сразу; больше — в очереди, уведомление «Файл готов», файл хранится 24 часа, скачивается по ссылке с проверкой прав (подписанная ссылка на 10 минут при каждом нажатии — раздел 03).

### 5.2 Как устроен файл

| Элемент | Правило |
|---|---|
| Имя файла | `PrimeMobile_<отчёт>_<период>_<дата выгрузки>.xlsx`, латиницей, без пробелов: `PrimeMobile_Prodazhi-po-modelyam_2026-11-01_2026-11-08_2026-11-09.xlsx` |

## 6. Печать: общие правила и принтеры

### 6.1 Оборудование

Модели в магазине — **не проверено** (архитектура, «Что нужно от Кайрата», п. 4). Допущение: Xprinter, самые распространённые в РК серии.

| Задача | Принтер (Допущение) | Бумага / этикетка | Язык команд |
|---|---|---|---|
| Чек, итог смены, квитанция | Xprinter XP-58 (58 мм) или XP-80 (80 мм), USB | термолента 58 или 80 мм | ESC/POS |
| Термоэтикетки на коробки, ценники-стикеры | Xprinter XP-365B / XP-360B / XP-420B (термо, 203 dpi), USB | этикетки 58×40, 40×30, 30×20 мм | TSPL |
| A4: гарантийный талон, накладные, акт trade-in, ценники листом | любой A4-принтер магазина (лазерный) | A4 | драйвер Windows |
| С iPhone | AirPrint-принтер A4, если есть; этикетки и чеки — через ноутбук магазина (п. 6.4) | — | — |

Допущение: этикеточный принтер работает в режиме этикеток с датчиком зазора (gap), а не непрерывной ленты.

### 6.2 Три способа печати

| Способ | Как работает | Где используем | Плюсы / минусы |
|---|---|---|---|
| **1. Браузер (базовый)** | Сервер отдаёт HTML-страницу точного размера (CSS `@page { size: 58mm 40mm; margin: 0 }`), открывается окно печати Chrome, пользователь выбирает принтер. Для A4 — PDF (dompdf или Gotenberg, архитектура 1) или тот же HTML | всё, на этапе 1 — единственный | работает везде, без установки; минус — окно выбора принтера каждый раз и риск неверного масштаба |
| **2. QZ Tray (тихая печать)** | На ноутбуке установлена программа QZ Tray. Страница отправляет ей задание: «принтер Xprinter XP-365B, PDF 58×40 мм» или «команды TSPL». Окна печати нет | ноутбук магазина: этикетки и чеки — сразу после проведения | быстро и без ошибок масштаба; минус — установка и сертификат подписи |
| **3. Очередь «принтер магазина»** | Задание печати создаётся на сервере и привязывается к магазину. Ноутбук с открытой страницей «Станция печати» (QZ Tray) забирает его и печатает | с iPhone владельца и продавцов: этикетки после прихода, чек после продажи с iPhone | печать этикеток с iPhone без Bluetooth-принтера; минус — ноутбук должен быть включён |

**Решение:** этап 1 — способ 1 (как в архитектуре: «HTML-шаблон точного размера → печать из браузера»). Этап 3 — способы 2 и 3. Позже — прямые команды TSPL для этикеток (архитектура: «позже можно перейти на прямую печать командами TSPL/ZPL»).

### 6.3 Настройка способа 1 (браузер) — инструкция в системе

Для ноутбука на Windows 7 / Chrome 109 в системе есть страница «Настройка печати» с картинками:
1. В драйвере Xprinter создать размер бумаги «58×40» (для этикеток) и «Лента 58» / «Лента 80» (для чеков).
2. В Chrome при первой печати: Принтер — Xprinter; Поля — «Нет»; Масштаб — «По умолчанию» (100 %); «Колонтитулы» — снять; «Фон» — включить. Chrome 109 запоминает последний принтер и параметры (не проверено для разных размеров подряд).
3. Кнопка «Тестовая печать» на каждый шаблон: печатается рамка точного размера, линейка в мм, штрихкод и QR. Если рамка обрезана — масштаб неверный.
4. Допущение: для чеков можно сделать отдельный ярлык Chrome с ключом `--kiosk-printing` — тогда чек печатается на принтер по умолчанию без окна. Но этот режим печатает **только на принтер по умолчанию**, поэтому для этикеток он не подходит — для них QZ Tray.

### 6.4 QZ Tray — требования (этап 3)

1. QZ Tray — бесплатная программа с открытым кодом; для тихой печати без окна «Разрешить?» задания подписываются сертификатом сайта. Нужен либо покупной сертификат QZ, либо самоподписанный с ручной установкой на ноутбук (не проверено: условия и цена сертификата QZ на 2026 год).
2. Работа на **Windows 7** — не проверено (новые версии QZ Tray могут не поддерживать Windows 7). Проверить в первый день этапа 3; если нет — остаётся способ 1.
3. Закрытый ключ подписи хранится **на сервере**, а не в браузере. Страница запрашивает подпись у сервера только для пользователя с правом печати.
4. В настройках магазина (Э26 → «Печать»): какой принтер для чеков, какой для этикеток, какой для A4 — выбираются из списка, который присылает QZ Tray.
5. Если QZ Tray не запущен — система сама переходит на способ 1 и пишет «Программа печати не запущена, открыто обычное окно печати».

### 6.5 Общие правила всех печатных форм

| Правило | Значение |

### Ф2. Чек возврата

Как Ф1, но заголовок «ҚАЙТАРУ ЧЕГІ / ЧЕК ВОЗВРАТА», № ВЗК-…, «по чеку № ПРД-… от {дата}», возвращённые позиции с IMEI, причина возврата, сумма к выдаче и способ, отменённые бонусы, подписи «Клиент получил деньги ______» и «Продавец ______». | Условия | текст из настроек фирмы (шаблоны «новый — 12 мес», «б/у — 1 мес», ссылка на ст. 30 закона о защите прав потребителей — **проверить юристом**, [`00-sfon-paritet.md`](00-sfon-paritet.md), п. 7) |
| Не гарантийные случаи | список из настроек: механические повреждения, следы влаги, вскрытие вне сервиса, программные изменения |
| Отметки о ремонтах | таблица на 3 строки: дата приёма, № ГР, работа, дата выдачи, подпись |
| Подписи | «Товар получил, с условиями ознакомлен: ______ / покупатель», «Продавец ______», место для печати (М.П.) |
| QR | «Проверить гарантию» → страница по секретной ссылке: товар, дата продажи, гарантия до, статус обращений |

**Сроки гарантии по умолчанию** (настройка фирмы, можно переопределить на модели и на экземпляре):

| Товар | Срок (Допущение, из шаблона sfon) |
|---|---|
| Новый телефон, планшет, часы | 12 месяцев |
| Б/у телефон | 1 месяц |
| Аксессуары | 14 дней на обмен; гарантия — нет, если в настройке аксессуара не указана |

«Гарантия до» = дата продажи + срок; если день не существует (31-е), берётся последний день месяца. Продление на время ремонта (раздел 01, П13) — талон перепечатывается с новой датой и пометкой «продлено до … (ремонт ГРО-…)».

### Ф4. Накладная

**Размер:** A4 книжный. Одна форма с 4 вариантами шапки.

| Вариант | Заголовок (kk / ru) | Стороны |
|---|---|---|
| Приход | «Тауарды қабылдау жүкқұжаты / Приходная накладная» | поставщик → магазин |
| Перемещение | «Ішкі ауыстыру жүкқұжаты / Накладная на перемещение» | магазин A → магазин B |
| Возврат поставщику | «Жеткізушіге қайтару жүкқұжаты / Накладная на возврат поставщику» | магазин → поставщик |
| Отпуск на сторону (продажа юрлицу / ИП) | «Қорларды босатуға арналған жүкқұжат / Накладная на отпуск запасов на сторону» | магазин → покупатель (с БИН) |

Допущение: для отпуска юрлицу форма близка к типовой «З-2» (форма из приказа Минфина РК — **не проверено**, сверить с бухгалтером). Остальные три — внутренние, форма свободная.

**Поля шапки:** № документа (ПРХ / ПРМ / ВЗП / ПРД), дата, организация (реквизиты фирмы), отправитель, получатель, основание (номер счёта поставщика / причина), валюта и курс (для прихода в $).

**Таблица:**

| № | Наименование | IMEI / штрихкод | Ед. | Кол-во | Цена | Сумма |
|---|---|---|---|---|---|---|

- В приходе и возврате поставщику — цена закупа в валюте документа и в ₸; **печатает только тот, кто видит себестоимость** (у остальных колонки цены нет).
- В перемещении — **без цен** (Допущение: перемещение не про деньги; при необходимости галочка «с розничными ценами»).
- Телефоны — по строке на экземпляр с IMEI; аксессуары — строка на позицию с количеством.

**Низ:** итого шт. и сумма (прописью — для отпуска на сторону), «Сдал ______ / Принял ______» с ФИО и датой, М.П.

### Ф5. Акт приёма б/у устройства (trade-in / выкуп) с ИИН

**Размер:** A4, **2 экземпляра** (сдающему и магазину), подпись на обоих. Текст — kk и ru. **Текст акта, согласия и заверений — проверить юристом** (архитектура 8, риски).

**Заголовок:** «Пайдаланылған құрылғыны қабылдау актісі / Акт приёма бывшего в употреблении устройства» № {ТРД-…} от {дата}, город, магазин.

**Поля:**

| Блок | Поля |
|---|---|
| Стороны | «Сдающий»: ФИО полностью, **ЖСН / ИИН** (12 цифр), удостоверение личности № и кем/когда выдано (Допущение: номер — да, кем выдано — по настройке), телефон. «Принимающий»: фирма, реквизиты, магазин, сотрудник |
| Устройство | тип, модель, память, цвет, **IMEI 1, IMEI 2**, серийный номер, «IMEI сверен с *#06#: да» |
| Госбаза IMEI | «Проверен {дата время}, результат: Верифицирован, источник: {imei.rfs.gov.kz / eGov}» (адрес официальной проверки — не проверено, [`00-kazakhstan.md`](00-kazakhstan.md), п. 1) |
| Состояние | грейд словами (A «Отличное», B «Хорошее», C «Заметные следы»), батарея %, заменённые детали, дефекты (список из чек-листа), комплект |
| Чек-лист | таблица пунктов с отметками ✔ / ✘: iCloud / Локатор выключен (Android — FRP отвязан), экран, корпус, вода, Face ID / Touch ID, камеры, динамики, микрофон, зарядка, кнопки, связь, сброс к заводским |
| Фото | 2 миниатюры (перед, зад), Допущение: печатаются, если A4 позволяет; иначе «фото: 4 шт. в системе» |
| Сумма | «Сумма выкупа: 150 000 ₸ (сто пятьдесят тысяч тенге)» — цифрами и прописью на ru (прописью kk — Допущение: позже, если библиотека не поддерживает) |
| Способ | «Выплачено наличными» / «Переведено Kaspi, операция № …» / «Зачтено в оплату чека № ПРД-…» |
| Заверения сдающего (галочки, печатный текст) | «Я являюсь собственником устройства», «Устройство не находится в залоге, рассрочке, не украдено», «Учётные записи (iCloud / Google) отвязаны», «Данные с устройства удалены, претензий к сохранности данных не имею» |
| Согласие на обработку персональных данных | текст из настроек (версия N от {дата}), «Согласен ______» |
| Подписи | «Сдал ______ / ФИО», «Деньги получил ______» (при выкупе), «Принял ______ / сотрудник», М.П. |

**Правила ИИН на печати** (архитектура 2.9, раздел 03):
1. При **первой печати** (проект для подписи и финальный акт сразу после проведения) ИИН печатается **полностью** — его только что ввёл продавец со слов сдающего, и без полного ИИН акт не имеет смысла.
2. **Повторная печать позже**: у владельца и админа — полностью (после PIN, запись в журнал «просмотр ИИН»); у продавца — `********1234` и пометка «ДУБЛИКАТ».
3. PDF акта не хранится на сервере в готовом виде (Допущение): он собирается при печати из зашифрованных данных. Скан подписанного акта — Допущение: можно сфотографировать и прикрепить, хранится в папке фирмы с доступом только В и А, срок хранения — настройка (по умолчанию 5 лет, **срок проверить юристом**).
4. Без отметки «Акт подписан» документ проводится, но висит в списке «Акты без подписи» (раздел 01, П12, шаг 8) и в О23.

### Ф6. Ценник телефона (полочный)

**Зачем:** на витрине магазина под телефоном. **Закон:** казахский обязательно, русский вторым ([`00-kazakhstan.md`](00-kazakhstan.md), п. 9; обязательные реквизиты ценника по правилам торговли РК — не проверено).

**Размер:** 70×50 мм, печать листом A4 по 8 штук (2 × 4) с линиями отреза; вариант — на этикеточном принтере 58×40 (настройка).

**Поля:**

| Место | Поле | Пример |
|---|---|---|
| Сверху, крупно | наименование kk | «iPhone 16 Pro 256 ГБ, Шөл түсі» |
| Под ним | наименование ru | «iPhone 16 Pro 256 ГБ, Desert» |
| Строка характеристик | Жады / Память, Түсі / Цвет, для б/у: «Қолданылған / Б/у · B Жақсы / Хорошее · Батарея 87 %» | — |
| Крупно | **Бағасы / Цена: 549 000 ₸** | — |
| Если цена снижена | старая цена зачёркнута мелко | ~~579 000 ₸~~ |
| Рассрочка (если включена в настройках и есть способ «рассрочка 0-0-24») | «Бөліп төлеу / Рассрочка: 22 875 ₸ × 24 ай / мес» | 549 000 / 24 = 22 875 ₸ |
| Справа внизу | QR на страницу телефона на сайте | `https://<домен>/phone/PM-10530` |
| Под QR | код `PM-10530` | — |
| Слева внизу | название магазина / юр. название, дата печати | «Prime Mobile · 09.11.2026» |

Правила:
1. **Нет названия на казахском — ценник не печатается** (раздел 01, П7; список «Нет перевода» Э24.4). Сообщение: «Нет казахского названия у 3 товаров. Добавьте перевод».
2. Сумма в месяц для рассрочки = цена / месяцев, **вверх до целого тенге** (покупатель не должен увидеть меньше, чем заплатит). Пример: 489 000 / 24 = 20 375 ₸; 219 000 / 24 = 9 125 ₸; 199 990 / 12 = 16 665,83 → 16 666 ₸.
3. После смены цены (Э13) телефон попадает в список «Перепечатать ценники» — кнопка «Печать N ценников» печатает пачку. Пока ценник не перепечатан, в Статистике задача «N ценников с устаревшей ценой» (Допущение: ценник считается перепечатанным после нажатия «Печать»).
4. QR ведёт на страницу телефона на сайте. Если телефон скрыт с сайта — QR не печатается (Допущение), иначе покупатель увидит 404.

### Ф8. Термоэтикетка / ценник аксессуара

**Размер:** 40×30 мм (по умолчанию) или 30×20 мм (мелкие товары, без QR).

| Поле | 40×30 | 30×20 |
|---|---|---|
| Название kk (жирно, 2 строки максимум, обрезка «…») | да | да, 1 строка |
| Название ru | да | нет (Допущение; если закон требует ru на ценнике — не проверено, тогда только 40×30) |
| Цена | крупно | крупно |
| Штрихкод | заводской EAN-13 или внутренний | да |
| Артикул | мелко | нет |

**Внутренний штрихкод** (если у товара нет заводского): EAN-13 с префиксом **2** (диапазон 20–29 зарезервирован для внутреннего использования магазинами) — `2` + 2 цифры фирмы + 9 цифр номера аксессуара + контрольная цифра. Генерируется при создании аксессуара, уникален в фирме. Пример: `2010000004524` (контрольная цифра 4).

### Ф9. Квитанция о приёме на гарантию

Лента 80 мм или A5. № ГРО-…, дата и время, магазин, клиент (имя, телефон), товар с IMEI, дата продажи и «гарантия до», жалоба, внешний вид при приёме (текст + «фото: 3 шт.»), комплект, «Пароль не храним — устройство принято без пароля / клиент вышел из iCloud», ориентировочный срок («до 10 дней на ремонт, до 30 дней на решение» — сроки по закону не проверено), QR «Статус ремонта», подписи «Сдал» / «Принял». Два экземпляра.

### Ф10. Итог смены (нефискальный Z-отчёт)

Лента 58 / 80 мм. «АУЫСЫМ ҚОРЫТЫНДЫСЫ / ИТОГ СМЕНЫ», № СМН-…, магазин, кто открыл и закрыл, время.
Блоки: продажи (чеков, сумма) → по способам оплаты (как О5) → возвраты → расходы из кассы → инкассация и переводы → наличные: на открытии, приход, расход, по учёту, посчитано, разница → подпись продавца и принявшего кассу. Без себестоимости и прибыли (печатает продавец).

### Ф11. Квитанция о долге (расписка клиента)

A5. Допущение: печатается при продаже в долг, подписывается клиентом, хранится в магазине. Поля: № чека, дата, клиент (ФИО, телефон, Допущение: ИИН — нет, только по решению Кайрата), товар с IMEI, сумма покупки, сумма долга, «вернуть до {дата}», график, если частями, текст обязательства (из настроек, **проверить юристом**), подписи клиента и продавца. Это не договор займа — юридическую силу проверить юристом.

### Ф12. Акт сверки долга

A4. С клиентом или поставщиком за период: остаток на начало, таблица операций (дата, документ, «увеличение долга», «уменьшение долга»), остаток на конец; для поставщика в $ — в $ и в ₸. Подписи сторон. Кнопка в О19 / О20 и в карточке контрагента. При переносе из sfon этот же акт печатается для «подписания списка долгов» (архитектура 5, шаг 5).

## 8. Штрихкоды и QR

| Что кодируем | Тип | Правило |
|---|---|---|
| IMEI (15 цифр) | Code 128 (набор C с переключением для нечётной цифры) | модуль не меньше 2 точек при 203 dpi (≈ 0,25 мм) → ширина ≈ 38–40 мм с тихими зонами, влезает в 58 мм. Высота полос ≥ 8 мм |
| `PM-код` | Code 128 | для этикеток без IMEI и для ценника (опционально) |
| Аксессуар | EAN-13 (заводской или внутренний «2…»), иначе Code 128 по артикулу | — |
| Ссылка на сайт | QR, коррекция ошибок M | размер не меньше **12×12 мм** на термоэтикетке и **15×15 мм** на ценнике и чеке; адрес короткий: `https://<домен>/p/PM-10530` (Допущение: короткий путь `/p/` перенаправляет на `/phone/PM-10530`, чтобы QR был проще и читался с ценника) |
| Электронный чек и гарантия | QR | секретная ссылка вида `https://<домен>/r/<случайные 22 символа>`; без IMEI и телефона в адресе |
| Бейдж сотрудника | Code 128 | код бейджа (раздел 03) |

Правила:
1. Штрихкоды и QR генерируются **на сервере** как SVG (для HTML и PDF) — чёткие при любом масштабе. Для QZ Tray / TSPL — нативные команды принтера `BARCODE` / `QRCODE` (позже).
2. Под каждым штрихкодом печатаются цифры (на случай, если сканер не читает).
3. Тестовая печать (п. 6.3) включает каждый тип штрихкода — продавец проверяет сканером при настройке.
4. Сканер ноутбука работает как клавиатура (архитектура Д4): касса принимает и IMEI, и `PM-код`, и EAN-13 в одно поле.

## 9. Казахский язык в печати

1. **Источник названий:** `name_kk` и `name_ru` в справочнике моделей, цветов и аксессуаров (архитектура 2.2; [`00-kazakhstan.md`](00-kazakhstan.md), п. 9). Память и ОЗУ («256 ГБ») не переводятся; «ГБ» на казахском тоже «ГБ».
2. **Постоянные тексты форм** (заголовки, подписи, «Итого», «Спасибо») — в файле переводов системы, одном на все формы. Список строк для перевода (около 120) выгружается кнопкой «Тексты для переводчика» в Excel: ключ, ru, kk. Допущение: перевод делает носитель языка по заказу Кайрата, разработчик вставляет готовый файл.
3. **Тексты фирмы** (условия гарантии, согласие, заверения в акте) — в настройках фирмы на kk и ru, по одному полю на язык. Пустое поле kk — форма печатается, но владелец видит предупреждение «Нет казахского текста гарантии».
4. **Порядок языков:** на ценнике — kk первым, крупнее или того же размера (не мельче ru). На чеке, талоне, акте, накладной — kk | ru (две колонки на A4/A5) или kk над ru (на ленте). Настройка «только ru» не действует для ценников.
5. **Шрифт и символы:** Ә Ғ Қ Ң Ө Ұ Ү Һ І и ₸ проверяются тестовой страницей в первый день (архитектура 0) — на A4 (PDF), на ленте 58/80 мм и на этикетке 58×40. Если принтер печатает текст встроенным шрифтом (ESC/POS / TSPL), казахские буквы заменяются «?» — поэтому текст всегда отправляется картинкой (растр), а не символами.
6. **Сумма прописью** на казахском (акт trade-in, накладная на отпуск) — Допущение: если готовой библиотеки нет, этап 3 — только ru прописью, kk — цифрами.

|---|---|---|
| `report_daily` | сводка по дням: фирма, день, магазин, продавец, вариант или аксессуар, состояние, источник → шт., продажи, возвраты, себестоимость, скидки | пересобирается из документов; ночная сверка |
| `report_daily_payments` | день × магазин × способ × счёт → число оплат, сумма, комиссия | то же |
| `report_daily_stock` | конец дня × магазин × вариант / аксессуар × статус → шт., себестоимость, розница | пишется ночью за прошедший день; для прошлых дат до запуска не строится (с дня X) |
| `site_stats_daily` | день × `PM-код` → просмотры, клики WhatsApp / рассрочка / бронь | без IP и персональных данных |
| `sale_lines.list_price_kzt` | цена по прайсу на момент продажи | новое поле, нужно для скидок (п. 2.1, правило 7) |
| `print_templates` | фирма, форма (Ф1–Ф12), размер, язык, версия, HTML-шаблон / тексты, активна | версии не удаляются; документ запоминает, какой версией печатался |
| `print_jobs` | фирма, магазин, форма, документ, кто, устройство, способ (браузер / QZ / очередь), принтер, копий, статус (создано / отправлено / напечатано / ошибка), «дубликат» да/нет, время | журнал печати; только добавление; источник для «ДУБЛИКАТ» и аудита |
| `print_settings` | магазин → принтер чеков, ширина ленты, принтер этикеток, размер этикеток, принтер A4, автопечать, копии, режим языка | меняет админ, владелец |
| `notification_settings` | пользователь → какие сводки, время, каналы (пуш, Telegram), пороги событий | — |
| `exports` | кто, отчёт, фильтры, строк, файл, создан, истекает | файл удаляется через 24 часа, запись остаётся |
| `public_links` | секретная ссылка → документ (чек, талон, квитанция), срок жизни | токен случайный, 22+ символа; в адресе нет данных |
